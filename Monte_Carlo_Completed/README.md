## What is observed and what is simulated

The CSV contains 82,767 patient-summary rows and 32 columns. It has demographics, conditions, laboratory values, survey variables and wearable summaries. It does **not** contain timestamped Fitbit observations, continuous glucose histories, sleep stages, event follow-up or a verified source-linkage manifest. The eligible age cohort contains 59,135 unique IDs.

The already-joined patient ID is the static alignment key. Original linkage accuracy cannot be established from this table. All seven-day, 15-minute glucose, heart-rate, blood-pressure, HRV, stress and breathing trajectories are synthetic, conditional on source-derived covariates. There is no live wearable connection. CGM is an additional simulated modality, not a Fitbit glucose measurement. Summary missingness is measured before imputation.

Complete resting-HR/HRV/breathing summaries have just **43 distinct triplets across 35,909 rows**, with every complete triplet repeated and up to 878 rows sharing a triplet. This is observed summary reuse, not proof of wearer identity. The supplied patient-ID split cannot establish independence of unprovided original Fitbit wearer IDs. Do not describe the cohort as 59,135 independently observed Fitbit streams.

Missing input values use medians fitted to training patients only. Missingness flags accompany model inputs. Unknown gender and smoking status are marked missing rather than labeled female or current smoker. Source IDs group every bootstrap copy into one partition. All future outcome labels are generated by the simulator; predictive accuracy here establishes a working algorithm inside that simulator, not clinical accuracy.

## Mathematical methods

Each run samples 1,500 source rows with replacement, groups copies by original identity into approximately 60% train / 20% validation / 20% test, and independently resimulates seven days. The first 24 hours are initialization burn-in. Decisions occur every two hours, with complete two-hour future windows. No features use a future observation.

### Dynamics

The supplied discrete-time kernels are retained. At a 15-minute step, glucose follows:

`G[t] = clipped(G[t-1] + 3*kappa*(mu-G[t-1]) + sigma*epsilon[t] + 0.9*meal_shock[t])`

`mu = 85 + 25*diabetes + 0.25*BMI + 0.3*(age-40)*diabetes`

`eff = exp(-0.35*clip(HbA1c-5, 0, 4))`, `kappa = 0.035*eff+0.005`, `sigma = 0.55+0.9*(1-eff)`.

Meals occur near 08:00, 13:00 and 19:30 with patient-specific timing jitter, random omission, random gamma shocks and snacks. Daily meal timing is reused within a trajectory, as in the supplied code. Glucose is bounded to 55–420 mg/dL with per-step fall/rise limits of 12/45. These are simulator choices, not physiological parameter estimates.

HR is a circadian curve plus activity, stress and hypertension contributions. Source resting HR initializes the trajectory; subsequent values use the original circadian kernel. SBP and HRV use discrete mean reversion with Gaussian noise and stress coupling. Stress is a bounded mean-reverting index. Parameters are fixed assumptions. No physiological parameter-posterior uncertainty or external calibration is claimed.

### Event targets

The next-two-hour glucose label is positive if either:

1. `max(G[t+1:t+8]) >= 180 mg/dL` while current glucose is below 180; or
2. the future maximum exceeds current glucose by at least 70 mg/dL.

This is a modeled event rule, not a validated medical definition. Tail windows without a complete future horizon are excluded. The weekly cardiovascular label is a synthetic rule: mean night HR >68 bpm, night HRV <28 ms and night breathing >17/min. It is not a diagnosis. Weekly Model A predicts any modeled glucose decision-window event after burn-in or this cardiovascular rule. Its target differs from Model B's two-hour glucose target.

### Predictive models and value decomposition

Model A is standardized logistic regression using clinical baseline inputs only. Model B is the supplied ReLU shared-layer multitask network, optimized by Adam, with a spike probability head, a two-hour SBP head and a two-hour stress head. Regression targets are standardized using training data. Its loss is:

`Huber(SBP_z) + 0.3*MSE(stress_z) + BCE(event) + (mean(p)-mean(y_train))^2`.

The final term constrains marginal calibration and does not guarantee conditional calibration. SBP error is reported in **mmHg**; glucose and intervention effects use **mg/dL**. Stress error uses the dimensionless 0–1 index. Each model has its own train-fitted scaler.

Four paired ablations use exactly the same target and held-out windows:

1. Clinical baseline features.
2. Clinical + wearable summaries and synthetic wearable/SBP history, excluding glucose and dynamic stress.
3. Add synthetic CGM history and recent-meal indicator.
4. Add psychological summaries and dynamic stress context.

Clinical inputs include age, gender indicator, BMI, HbA1c, baseline glucose, diabetes, hypertension, heart disease, smoking, kidney disease, stroke, physical health days and general health. Wearable history includes HR, HRV, SBP and clock time. Psychological inputs include tension, tiredness, stress and mental-health days. SBP is a simulated monitoring channel; the label “wearables” does not imply that Fitbit measured BP. Source-derived mental-health fields are excluded from the clinical-only ablation.

The paired AUROC differences telescope arithmetically from clinical to full-model performance. They are predictive comparisons, not causal contributions or proof that every added modality helps. Each network is trained separately. Other metrics include average precision, Brier score, constant-risk Brier baseline, fixed-bin ECE and regression MAE.

The alert threshold maximizes **F2 on validation windows only**, favoring recall. This is a research operating point, not a clinician-approved threshold. The original fixed 0.30 threshold is also reported. All alert precision, recall and lead-time metrics use test identities only. Crossing lead time is measured only for alerts strictly before a crossing and no more than two hours before it. Window recall and crossing recall have different denominators.

### Micro-randomized trial

At each daily decision, availability is Bernoulli(0.8), and available patients are randomized to a prompt with probability 0.5. The synthetic next-day peak potential outcome is reduced by:

`beta(s) = 4 + 8*(s+1.5)/3 mg/dL`, for clipped standardized baseline risk `s` in [-1.5,1.5].

Thus a 4–12 mg/dL benefit is **imposed**. It is not discovered from the CSV. Effects are estimated within risk tertiles by treatment-centered regression with risk interaction, previous-day glucose peak and day covariates. Standard errors use a sandwich covariance clustered by simulated trajectory, with small-sample adjustment and t intervals. True stratum means, per-run interval coverage and estimated effects are saved. No untreated future potential outcome enters the estimator's covariates. This verifies effect recovery under the randomized simulator assumptions and cannot establish treatment efficacy in people.

## Interpretation of uncertainty

Summary intervals are the empirical 2.5th and 97.5th percentiles across 40 independent seeded simulator runs and bootstrapped cohorts. They are **simulation variability ranges**, not 95% clinical confidence intervals or a confidence interval for the mean. Forty runs provide relatively coarse tail estimates. MRT per-run cluster intervals are separate fields. Original identities may recur across runs, so variation does not represent 40 independent real-world cohorts.

## Doctor interaction

The local Streamlit UI provides five test trajectories selected by baseline-risk quantiles. It does not select examples by future events or alert success. A doctor can choose a virtual patient, replay history, inspect the latest two-hour probability and supporting glucose/HR/SBP histories, adjust the displayed alert threshold, review aggregate model performance and examine measured data coverage. Future outcomes require an explicit retrospective toggle. Notes remain in the app session. A downloadable replay snapshot records research settings only; it is not a medical record or an intervention order.

## Privacy and provenance

Processing stays local. There is no cloud upload, telemetry-enabled dashboard, live patient connection or raw CSV in the delivery package. Original patient IDs are excluded from the dashboard and JSON examples, replaced with independent VT labels. Example ages use five-year bands. JSON examples contain source-derived baseline flags and model outputs, so they are **not certified anonymous**. Local model replay vectors contain derived source covariates and should be handled with the same care as the input. The audit reports quasi-identifier uniqueness with a **record-weighted denominator**, separately from class-weighted statistics.

The source CSV's original license, EHR-to-wearable matching procedure, anonymization status and claimed synthetic origin were not provided. Merely having a numerical patient ID or generating synthetic trajectories does not certify the source. The local code uses the supplied dataset under the user's instruction. Before external sharing, obtain a provenance/license record and a formal privacy assessment; for a strictly synthetic public demo, replace the source-derived baselines and replay vectors with a documented fully synthetic input.

[HHS guidance](https://www.hhs.gov/hipaa/for-professionals/special-topics/de-identification/index.html) describes Safe Harbor and Expert Determination as HIPAA de-identification methods. This prototype implements neither a complete Safe Harbor assessment nor an Expert Determination. Its k-anonymity-style check is a limited diagnostic.

[MeitY's official DPDP Rules page](https://www.meity.gov.in/documents/act-and-policies/digital-personal-data-protection-rules-2025-gDOxUjMtQWa?pageTitle=Digit) and the [2025 Gazette rules](https://www.meity.gov.in/static/uploads/2025/11/53450e6e5dc0bfa85ebd78686cadad39.pdf) are the primary legal references checked on 20 October 2026. Applicable commencement dates and obligations require assessment for the actual use. No HIPAA or DPDP compliance certification is made.
